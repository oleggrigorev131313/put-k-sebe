# Путь к себе — backend

Backend для Telegram Mini App на Yandex Cloud: API Gateway → Cloud Functions (Python 3.12) → YDB Serverless.

## Что входит

- Серверная проверка подписи Telegram Mini App initData. Клиентские данные initDataUnsafe не используются для авторизации.
- Облачное сохранение состояния пользователя (дневник, паттерны, выполненные практики, onboarding).
- Обязательная изоляция данных по Telegram user ID.
- Lockbox для токена бота; токен не попадает в GitHub и браузер.
- Отдельная таблица событий использования без содержимого дневников. В ней хранится Telegram user ID, поэтому эти события псевдонимизированы, а не анонимны.
- API: GET /health, GET/PUT/DELETE /v1/state.

## Что пока не подключено

- ИИ-анализ, автопредложение паттернов и AI Studio.
- Платежи, подписки и Tribute.
- Панель администратора (аналитические события уже записываются; доступ к сводке добавим с отдельной проверкой Telegram ID администратора).
- Завершённый юридический контур для обработки персональных данных. До публичного запуска нужны тексты согласия, политика конфиденциальности, сроки хранения и порядок удаления, проверенные с юристом по применимому законодательству.

## Развёртывание

Одна команда в Cloud Shell:

    curl -fsSL https://raw.githubusercontent.com/oleggrigorev131313/put-k-sebe/main/backend/deploy.sh -o /tmp/put-k-sebe-deploy.sh && bash /tmp/put-k-sebe-deploy.sh

Скрипт сам скачивает TAR-архив актуальной версии репозитория и распаковывает его во временную папку (без Git, чтобы не зависеть от ограничений файловой системы Cloud Shell). Он сначала покажет список создаваемых ресурсов и спросит подтверждение. При первом запуске токен Telegram-бота вводится скрыто и сохраняется в Lockbox.

Скрипт использует уже созданные облако, папку, базу и сервисный аккаунт. Он повторно использует Lockbox secret, создаёт приватный Object Storage bucket для архива функции (архивы свыше 3,5 МБ Cloud Functions нужно загружать этим способом), назначает backend-сервисному аккаунту `storage.viewer` на папку, загружает ZIP и создаёт версию Cloud Function и API Gateway. Бакет по умолчанию не публичный. API Gateway использует отдельный service account только с правом вызова Cloud Function; он не получает доступ к YDB и Lockbox. Токен бота вводится через скрытый prompt в терминале.

Для загрузки большого ZIP скрипт использует поддерживаемые Yandex Cloud параметры `--package-bucket-name` и `--package-object-name`. Бакет остаётся приватным и используется только временно для ZIP-пакета функции; после успешного создания версии объект удаляется.

После развёртывания скрипт напечатает API Gateway URL. Этот URL нужно добавить в frontend-конфигурацию и опубликовать новый commit в GitHub Pages.

## Переменные функции

- YDB_ENDPOINT — endpoint без database path.
- YDB_DATABASE — полный путь базы из endpoint.
- BOT_TOKEN — значение из Lockbox, передаваемое Cloud Functions как secret.

## Модель хранения

user_state содержит один JSON-документ на Telegram user ID. Дневниковые записи не доступны администратору через API.
analytics_events содержит тип события, Telegram user ID, время и служебные метаданные; тексты дневников туда не записываются. Поскольку Telegram user ID позволяет связать события с пользователем, такую таблицу нельзя считать анонимной.

Сервис предназначен для саморефлексии и не является медицинской диагностикой или лечением.
