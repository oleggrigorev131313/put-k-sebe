# Путь к себе — backend

Backend Telegram Mini App на Yandex Cloud: API Gateway → Cloud Functions (Python 3.12) → YDB Serverless. Секреты хранятся в Yandex Lockbox.

## Назначение

Backend обеспечивает Telegram-аутентификацию, облачное хранение состояния пользователя, тарифные ограничения, AI-инструменты саморефлексии, обработку платежных событий Tribute и отдельную продуктовую аналитику.

Универсального AI-чата в продукте нет и не планируется. AI вызывается только из целевых сценариев приложения: анализ записи, ежедневный Summary и, по мере реализации, персональные рекомендации/задания.

## Реализованные серверные сценарии

- Проверка подписи Telegram Mini App `initData`. Для авторизации используется серверная проверка; `initDataUnsafe` не является доверенным источником.
- Облачное сохранение пользовательского состояния: дневник, паттерны, практики и onboarding.
- Изоляция данных по Telegram user ID.
- Premium-статус и однократный семидневный trial на Telegram-аккаунт.
- AI-анализ записи через DeepSeek. В текущей реализации — не более пяти успешных анализов в день.
- Ежедневный AI Summary по записям текущего локального дня пользователя; результат кэшируется.
- Tribute webhook для обработки событий оплаты.
- Отдельные продуктовые события без текста дневника.
- Административный endpoint агрегированной аналитики с отдельным паролем.

## Тарифная модель

### Бесплатный доступ

Дневник, ручное ведение паттернов, история, прогресс и базовые практики.

### Premium

Персональный AI-анализ, ежедневный AI Summary и AI-рекомендации/задания по мере их реализации. Доступ предоставляется при активной покупке либо в течение однократного семидневного пробного периода.

Backend обязан проверять Premium самостоятельно на каждом защищённом AI-маршруте. Frontend-ограничения не являются механизмом авторизации. После окончания Premium AI-функции недоступны, бесплатные сценарии и сохранённые данные остаются доступны.

Текущие проверки Premium присутствуют в маршрутах анализа записи и Daily Summary. При добавлении новых AI-маршрутов необходимо повторить серверную проверку доступа и тесты отказа при истёкшем тарифе.

## Основные API-маршруты

- `GET /health` — проверка работоспособности и доступности схемы.
- `GET/PUT/DELETE /v1/state` — чтение, сохранение и удаление пользовательского состояния.
- `GET /v1/premium` — статус Premium.
- `POST /v1/trial` — активация пробного периода.
- `POST /v1/ai/analyze-entry` — анализ дневниковой записи.
- `POST /v1/ai/daily-summary` — ежедневный обзор.
- `GET /v1/ai/usage` — состояние дневного лимита.
- `POST /v1/ai/test` — служебная проверка соединения с AI-провайдером.
- `POST /v1/webhooks/tribute` — webhook платежного провайдера.
- `POST /v1/events` — запись разрешённых продуктовых событий.
- `GET /v1/admin/analytics` — агрегированная административная аналитика.

## Модель хранения

Таблицы создаются функцией `_ensure_schema()`:
- `user_state` — JSON-состояние пользователя.
- `analytics_events` — продуктовые события.
- `premium_purchases` — покупки Premium.
- `premium_trials` — пробные периоды.
- `ai_analyses` — результаты AI-анализа и Summary.

Дневниковые записи не должны попадать в `analytics_events` или технические логи. Аналитические идентификаторы HMAC-псевдонимизируются; это псевдонимизация, а не полная анонимизация.

## Переменные окружения

- `YDB_ENDPOINT` — endpoint YDB без database path.
- `YDB_DATABASE` — полный путь базы данных.
- `BOT_TOKEN` — токен Telegram-бота из Lockbox.
- `ADMIN_PASSWORD` — отдельный пароль админ-панели из Lockbox.
- `ANALYTICS_SECRET` — секрет HMAC-псевдонимизации.
- `DEEPSEEK_API_KEY` — ключ DeepSeek.
- `TRIBUTE_API_KEY` — ключ Tribute, если требуется текущей конфигурацией webhook.

Не помещайте реальные значения этих переменных в GitHub, сообщения, скриншоты или frontend.

## Развёртывание

В Cloud Shell:

```bash
curl -fsSL https://raw.githubusercontent.com/oleggrigorev131313/put-k-sebe/main/backend/deploy.sh -o /tmp/put-k-sebe-deploy.sh
bash /tmp/put-k-sebe-deploy.sh
```

Перед запуском внимательно проверьте выбранные cloud и folder, список ресурсов и действия скрипта. Развёртывание меняет облачную инфраструктуру; не используйте его как диагностическую команду. Сначала собирайте read-only сведения и логи.

Скрипт использует ресурсы Yandex Cloud, описанные в его исходнике. Конкретный состав ресурсов, IAM-права, переменные и версии следует проверять по текущей конфигурации Cloud Function, API Gateway, YDB и Lockbox, а не полагаться только на эту документацию.

## Диагностика

- Начинайте с `GET /health`, затем проверяйте конкретный API-маршрут.
- HTTP 503 от общего обработчика может означать необработанное исключение; сам код статуса не устанавливает первопричину.
- Для расследования нужны логи соответствующего вызова Cloud Function и request/trace ID.
- Ошибка CLI при чтении логов (например, `UNAVAILABLE`) сама по себе не доказывает ошибку приложения.
- Не меняйте секреты и не запускайте повторный deploy до локализации проблемы.
- Не логируйте request body, Telegram `initData`, токены, пароль администратора или содержимое дневника.

## Безопасность и конфиденциальность

Данные дневника и анкеты могут содержать очень личную информацию. Обеспечивайте изоляцию по пользователю, минимальные права сервисных аккаунтов, серверную проверку тарифов, безопасную обработку webhook и отдельную защиту административного доступа.

Приложение предназначено для саморефлексии и не является медицинской диагностикой или лечением.
