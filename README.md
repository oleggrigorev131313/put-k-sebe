# Путь к себе

Мобильное веб-приложение и Telegram Mini App для самостоятельной рефлексии.

## Публикация
- Файл приложения: `index.html` (вся логика, стили и разметка находятся внутри одного файла).
- Для GitHub Pages выберите **Settings → Pages → Deploy from a branch → main → /(root) → Save**.
- Адрес: https://oleggrigorev131313.github.io/put-k-sebe/

## Возможности
- Пошаговый дневник мыслей по принципам КПТ.
- Запись ситуации, эмоции, автоматической мысли, фактов за и против, сбалансированной формулировки и следующего шага.
- Личные повторяющиеся паттерны.
- Прогресс на основе фактических записей.
- Библиотека коротких практик.
- Экспорт и импорт резервной копии JSON.
- Telegram WebApp SDK: кнопка готовности и раскрытие мини-приложения.

## Ограничения первой версии
- Данные хранятся только локально в браузере/WebView пользователя. Нет аккаунтов, облачной синхронизации, ИИ, платежей и серверной базы данных.
- Очистка данных браузера или приложения может удалить записи. Пользователю следует регулярно экспортировать резервную копию.
- Приложение — инструмент самостоятельного наблюдения и обучения навыкам рефлексии; оно не ставит диагнозы и не заменяет профессиональную помощь.
- Не вводите в дневник сведения, по которым можно идентифицировать вас или других людей.

## Подключение Telegram
В @BotFather: `/setmenubutton` → выбрать бота → текст `Путь к себе` → URL выше. Ссылка начнёт работать после включения GitHub Pages и завершения публикации.

Команда `/start` в чате бота (не внутри Mini App) отвечает фото и кнопкой «Открыть дневник». Обработчик — та же Cloud Function, путь шлюза `POST /v1/webhooks/telegram`. Одноразовая установка webhook и деплой описаны в `backend/README.md`.


## Продуктовая спецификация AI (согласовано 2026-11-13)

### Принципы тарифов и аналитики
- Ежедневный персональный обзор предоставляется каждый день и на бесплатном, и на Premium-тарифе.
- Сводка создаётся строго один раз за локальные календарные сутки пользователя — одинаково на бесплатном и Premium-тарифе. Повторного запуска нет ни на одном тарифе, включая Premium.
- Пользователь может запустить сводку вручную после завершения работы с дневником. Если он этого не сделал, серверный планировщик запускает её в 23:59 по часовому поясу устройства пользователя. Открытие приложения или переход между вкладками не запускают генерацию.
- Серверный таймер срабатывает каждую минуту, выбирает пользователей, у которых локальное время 23:59, и вызывает генерацию. Ограничение на один запуск проверяется на backend.
- Краткий анализ дневниковой записи — отдельная операция с тарифным лимитом.
- Личный чат: небольшой бесплатный лимит, далее правила дополнительных AI-кредитов будут определены отдельно. Решение о сроке действия и сгорании дополнительных кредитов пока НЕ принято.
- Не реализовывать безлимитные AI-обращения.
- AI-кредиты списывать только за успешно выполненные операции; предусмотреть резервирование и возврат при ошибке, защиту от повторных запросов и серверные лимиты.

### Ежедневный аналитик и адаптация практик
Ежедневный обзор учитывает:
1. Новые записи дневника и результаты краткого анализа.
2. Эмоции, автоматические мысли, фактические подтверждения и опровержения.
3. Подтверждённые паттерны и гипотезы, которые ещё требуют проверки.
4. Назначенные практики, выполнение/невыполнение и обратную связь пользователя о сложности и полезности.
5. Предыдущие рекомендации и динамику пользователя.

Результат:
- содержательный обзор дня;
- наблюдения о повторяющихся темах без постановки диагнозов;
- задания на следующий день с учётом дневника и выполнения предыдущих практик;
- объяснение, почему предложено именно это задание.

Если за день нет новых записей и значимых изменений по практикам, не запускать дорогостоящий повторный анализ без необходимости. Планировщик должен учитывать часовой пояс пользователя и идемпотентность ежедневного задания.

### Практики и задания
- Хранить назначение задания отдельно от факта выполнения.
- Фиксировать статус: назначено, выполнено, пропущено, отложено или заменено.
- После выполнения предлагать короткую обратную связь о сложности и полезности.
- AI может адаптировать сложность, менять упражнение или предлагать паузу, но пользователь всегда может принять, изменить или отклонить рекомендацию.
- Не считать невыполнение признаком неуспеха пользователя.

### Позиционирование ограничений
Объяснять пользователю, что лимиты нужны для осознанного использования помощника и развития самостоятельности: AI помогает анализировать и поддерживает, но не должен принимать решения и нести ответственность за жизнь вместо человека. Не формулировать это как упрёк или наказание.

### Предварительная оценка стоимости GPT-6 Astra API
Модель API: `gpt-6-astra`. Ориентир стандартной цены короткого контекста: $10 за 1 млн входных токенов и $50 за 1 млн выходных токенов. Фактическая стоимость зависит от длины контекста, ответа, reasoning tokens, кеширования и режима обработки; перед запуском перепроверить официальный прайс.

Иллюстративные бюджеты для расчёта, не гарантированные фактические расходы:
- Краткий анализ записи: 4 000 входных + 1 000 выходных токенов ≈ $0.09.
- Ежедневный обзор с заданиями: 12 000 входных + 2 000 выходных ≈ $0.22.
- Сообщение в чате: 2 000 входных + 700 выходных ≈ $0.055.

При 30 ежедневных обзорах пользователь уже создаёт около $6.60 расходов API в месяц на Astra, даже без чата и анализа отдельных записей. Эти оценки не включают инфраструктуру, налоги, комиссии, повторные вызовы и иные накладные расходы. До утверждения тарифной цены нужно провести тестовые замеры токенов на реальных сценариях и заложить запас на пики потребления.


## Аналитика и админ-панель

- Админ-панель: `https://oleggrigorev131313.github.io/put-k-sebe/admin.html` (доступ появится после публикации GitHub Pages).
- Админ-панель показывает список профилей, Telegram ID, имя/username, тариф, счётчики записей, практик и паттернов, последнюю активность, DAU/WAU/MAU и историю событий.
- В карточке пользователя доступны дневниковые записи, паттерны, практики, AI-ответы (если пользователь разрешил хранение AI-истории) и история действий.
- Тексты дневника и анкеты хранятся отдельно в `user_state` для синхронизации. Они не отправляются в таблицу продуктовых событий. События хранят HMAC-псевдоним Telegram ID.
- Профиль с Telegram ID, именем, username и часовым поясом регистрируется после принятия пользователем настроек конфиденциальности. Старые аккаунты появятся в списке после следующего открытия приложения.
- Если пользователь отключил хранение AI-истории, тексты AI-запросов и ответов не доступны в админке; метаданные активности учитываются отдельно.
- Для включения новых API и таймера нужно выполнить обновлённый `backend/deploy.sh`. Скрипт обновляет Cloud Function и API Gateway, настраивает IAM и создаёт Timer Trigger в Yandex Cloud. Перед запуском нужно подтвердить эти изменения.
